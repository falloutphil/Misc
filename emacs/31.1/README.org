* Emacs 31.1 on Debian 13 / Trixie
Emacs 31.1 on Trixie now uses Debian's native WebKitGTK 4.1 packages for
xwidgets. The older private =/opt/icu75= and =/opt/wk240= WebKit stack
remains only in the Emacs 30.2 scripts.

The Wayland/PGTK build was validated on this machine with Trixie's
=libwebkit2gtk-4.1-dev=; it built, stowed as the default
=/usr/local/bin/emacs=, loaded =xwidget-internal=, linked to native
WebKitGTK 4.1/libsoup3, and Doom rebuilt successfully under Emacs 31.1.

The X11 script is the matching GTK3/X11 native-WebKit recipe for 31.1.
It uses the same Debian WebKitGTK 4.1 package and feature set, but
should still be runtime-tested on an actual X11 session before treating
the X11 flavour as proven in the same way as Wayland.

** Scripts
Wayland/PGTK:

#+begin_src bash
emacs/31.1/debian_13_trixie_wayland_pgtk/emacs-wayland-pgtk-native-webkit-build-trixie.sh --clean=none
#+end_src

X11/GTK3:

#+begin_src bash
emacs/31.1/debian_13_trixie_x11_gtk3/emacs-x11-native-webkit-build-trixie.sh --clean=none
#+end_src

Both scripts support:

#+begin_src text
--clean=none   reuse downloaded source and rebuild Emacs
--clean=light  remove extracted Emacs source and rebuild
--clean=deep   remove the workroot and rebuild
#+end_src

The scripts install through GNU Stow and make the new package the active
default by unstowing other =emacs-*= packages from =/usr/local= first.
Existing Stow packages are not deleted, so rollback to 30.2 remains
available.

** WebKit Change
Emacs 30.2 needed a pinned private WebKitGTK 2.40.x build because its
configure logic rejected newer WebKit versions and xwidgets were fragile
across WebKit, libsoup, compositor, and WSLg combinations.

Emacs 31.1 removed the old WebKit upper-bound and configures against
=webkit2gtk-4.1=. On Trixie this means:

#+begin_src text
libwebkit2gtk-4.1-dev
libsoup-3.0-dev
#+end_src

The validated Wayland build linked to Debian WebKitGTK =2.54.0= and
libsoup =3.6.5=.

Wayland uses =--with-pgtk=. X11 uses =--with-x-toolkit=gtk3=.

=texinfo= is installed to avoid the =makeinfo >= 4.13= warning and keep
manual rebuilds available.

** Installing A Built Stow Package Elsewhere
The build result is a normal GNU Stow tree under =/usr/local/stow=. For
the validated Wayland build the package is:

#+begin_src text
/usr/local/stow/emacs-31.1-pgtk-nativewk
#+end_src

That tree can be copied to another Debian 13 / Trixie machine with the
same CPU architecture, such as another Wayland laptop. It is not a
standalone static bundle: the target machine still needs the matching
Debian runtime libraries, especially native WebKitGTK 4.1/libsoup3,
GTK3, libgccjit, tree-sitter, image libraries, sound/media libraries,
GLib networking, bubblewrap, and xdg-dbus-proxy.

On the build machine:

#+begin_src bash
cd /usr/local/stow
sudo tar -czf "$HOME/emacs-31.1-pgtk-nativewk-trixie-amd64.tar.gz" emacs-31.1-pgtk-nativewk
sudo chown "$USER:$USER" "$HOME/emacs-31.1-pgtk-nativewk-trixie-amd64.tar.gz"
#+end_src

Copy that archive to the other Trixie laptop, then on the target machine
install the runtime dependency set. The conservative option is to
install the same apt package list used by the build script; this
includes development packages, but it avoids missing-library surprises
and matches the tested environment.

Then install and activate the copied Stow tree:

#+begin_src bash
sudo mkdir -p /usr/local/stow
sudo tar -xzf emacs-31.1-pgtk-nativewk-trixie-amd64.tar.gz -C /usr/local/stow
for pkg in /usr/local/stow/emacs-*; do
  [[ -d "$pkg" ]] || continue
  sudo stow -D -d /usr/local/stow -t /usr/local "${pkg##*/}"
done
sudo stow -R -d /usr/local/stow -t /usr/local emacs-31.1-pgtk-nativewk
/usr/local/bin/emacs --version
/usr/local/bin/emacs -Q --batch --eval "(unless (featurep 'xwidget-internal) (kill-emacs 11))"
#+end_src

If you want the same Wayland helper launchers on the target machine,
install the 31.1 script from this repository and copy the two wrapper
definitions from its =install_wrappers= function, or run the script on
that machine instead of using the copied Stow tree.

** WSLg Incident: One Long Desktop Launcher Broke All Debian GUI Apps
*** What happened and when
On 16 October 2026, Debian's GUI applications stopped working under WSLg:
Chromium exited with =X connection error received= and GUI Emacs failed,
while terminal Emacs (=emacs -nw=) continued working. A fresh Ubuntu distro
on the same Windows machine ran both =xeyes= and Chromium successfully.
The Debian problem was fixed shortly after midnight on 17 October 2026
(Europe/London time), without reinstalling Debian.

The offending file was =/usr/local/share/applications/emacsclient.desktop=,
created on 11 October 2026 at 23:34:42 BST during the Codex-assisted Emacs
31.1 native-WebKit build/install. It belonged to Linux user =phil=.
Emacs's =make install= generates this desktop entry from its source
template; GNU Stow exposes it through =/usr/local/share/applications=.
It is installed even if Emacs is only launched from a terminal and no
Linux desktop session is used. The problem did not require clicking the
launcher or starting Emacs Client.

*** Why one launcher affected Chromium too
WSLg enumerates the distro's desktop entries and sends them to its
Windows =WSLDVCPlugin.dll= component to create Start-menu shortcuts.
The generated Emacs Client entry contained a shell conditional and two
copies of the long absolute path to the installed =emacsclient= binary.
Weston logged a 246-character exported command. WSLg's plugin adds its
own distro/working-directory launch prefix and formats the result with
=swprintf_s= into =WCHAR exeArgs[MAX_PATH]= (260 characters). The combined
command exceeded that buffer, invoking the C runtime's invalid-parameter
fail-fast handler and terminating =msrdc.exe=.

Because that process supports the shared GUI connection, all Debian GUI
apps lost their display. Chromium's GPU warning was not sufficient to
identify the cause. Weston subsequently crashed after losing its RDP peer.

The relevant Windows Application Error events were:

#+begin_example
Faulting application: msrdc.exe
Faulting module: WSLDVCPlugin.dll
Exception code: 0xc0000409
Fault offset: 0x00000000000118dc
#+end_example

Disassembly at that offset showed a fast-fail with subcode 5 (invalid
argument); the exception code alone should not be interpreted as proof
of a stack buffer overwrite. The failure reproduced with WSL 3.0.3 /
WSLg 1.0.79 and after rollback to WSL 2.7.14 / WSLg 1.0.73.2, on Windows
10.0.26300.9711. The rollback did not fix it. A general Windows-update
regression was initially suspected but was not established.

*** When to check this on another machine
After installing, rebuilding, or copying this Stow package onto a WSLg
machine, inspect the installed desktop entry, particularly if the install
prefix differs. The launcher text and added WSLg prefix must fit the
plugin's buffer. The raw =Exec= length alone does not include that prefix.

#+begin_src bash
readlink -f /usr/local/share/applications/emacsclient.desktop
awk '/^Exec=/{print length($0)-5, $0}' /usr/local/share/applications/emacsclient.desktop
tail -80 /mnt/wslg/stderr.log
#+end_src

Repeated =msrdc.exe ... exited with status 9= messages followed by
=exited more than 10 times in 60 seconds, not starting it again= warrant
checking Windows Application events for the faulting module. These log
messages alone do not prove this particular launcher is responsible.
Do not reinstall a distro solely because they appear.

*** Tested fix: keep the desktop Exec short
Move the conditional into a separate shell script and reference it from
the main desktop entry. This preserves reuse-frame behavior for file
arguments and create-frame behavior when launched without files.
The commands below match the tested Wayland package; adjust both binary
paths for a different Stow package or installation prefix.

#+begin_src bash
desktop=/usr/local/share/applications/emacsclient.desktop
# Preserve the original once; do not overwrite an existing incident backup.
sudo cp -pn "$desktop" "$desktop.before-wslg-fix"
sudo tee /usr/local/share/applications/emacsclient-wslg-launcher.sh >/dev/null <<'EOF'
#!/bin/sh
if [ "$#" -gt 0 ]; then
    exec /usr/local/stow/emacs-31.1-pgtk-nativewk/bin/emacsclient --alternate-editor= --reuse-frame "$@"
else
    exec /usr/local/stow/emacs-31.1-pgtk-nativewk/bin/emacsclient --alternate-editor= --create-frame
fi
EOF
# Replace only the first (main) Exec entry, preserving Desktop Action entries.
sudo sed -i '0,/^Exec=/{s|^Exec=.*|Exec=sh /usr/local/share/applications/emacsclient-wslg-launcher.sh %F|;}' "$desktop"
sh -n /usr/local/share/applications/emacsclient-wslg-launcher.sh
#+end_src

The script is invoked through =sh=, so it does not need an executable bit.
The new main =Exec= value is 64 characters including =%F=, instead of the
long inline conditional. The original installed entry was backed up as
=emacsclient.desktop.before-wslg-fix=; the live file resolves into the
Stow package's =share/applications= directory.

If WSLg has already exhausted its client restart attempts, save work and
close any assistant running inside WSL before running =wsl --shutdown=
from Windows PowerShell. This stops WSL sessions and will kill an
assistant running inside Debian. Reopen Debian and test Chromium and
Emacs. During this incident, reconnecting the Windows RDP client with
its recorded session parameters avoided shutting down Debian; that was
a session-specific diagnostic recovery, not a reusable command.

Verification on 17 October: the RDP client survived application-list
synchronization, both Emacs shortcuts were created in the Windows
Start menu, and Chromium opened successfully, confirmed by the user.
No Debian reinstall was needed.

This is an installed-file workaround, not yet an automatic change in the
build scripts. A subsequent =make install= or rebuild can regenerate the
long entry: recheck and reapply the fix after such an installation.
Copying a Stow archive made before this fix can also reintroduce it.

** Rollback
To roll back from the validated Wayland 31.1 package to the existing
30.2 Stow package:

#+begin_src bash
sudo stow -D -d /usr/local/stow -t /usr/local emacs-31.1-pgtk-nativewk
sudo stow -R -d /usr/local/stow -t /usr/local emacs-30.2-pgtkwk
#+end_src

The X11 31.1 package name is:

#+begin_src text
emacs-31.1-x11-nativewk
#+end_src
